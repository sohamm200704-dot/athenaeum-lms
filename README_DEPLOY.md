# Athenaeum LMS — Deployment-Ready Edition

This version is prepared for public deployment with Flask + Gunicorn + PostgreSQL.
It can still run locally with SQLite if `DATABASE_URL` is not set.

## What changed

- PostgreSQL support through `psycopg`.
- `DATABASE_URL` environment-variable configuration.
- Production server: Gunicorn.
- Render Blueprint (`render.yaml`) for web service + PostgreSQL.
- `SECRET_KEY` is configurable and generated by Render in the Blueprint.
- `/health` endpoint for deployment health checks.
- Binds to `0.0.0.0` and the hosting `PORT`.
- SQLite fallback remains available for local testing.
- No local file is required for the deployed database; production data lives in PostgreSQL.

## Deploy on Render — easiest method

### Option A: Blueprint (recommended)

1. Create a GitHub repository and upload this entire project folder.
2. Open Render and choose **New → Blueprint**.
3. Connect your GitHub repository.
4. Render detects `render.yaml`.
5. The Blueprint creates:
   - `athenaeum-lms` Flask web service
   - `athenaeum-db` PostgreSQL database
6. Deploy the Blueprint.
7. Open the generated `https://...onrender.com` URL.
8. Test `/health`; it should report `status: ok` and `database: postgresql`.
9. Log in with one of the demo accounts above.

### Option B: Manual Render setup

Create a PostgreSQL database first, then create a Web Service connected to the same GitHub repo.

Web Service settings:

- Runtime: Python 3
- Build command: `pip install -r requirements.txt`
- Start command: `gunicorn app:app`
- Python version: `3.13`

Add these environment variables:

- `DATABASE_URL` = the PostgreSQL connection string from your Render database
- `SECRET_KEY` = a long random secret
- `FLASK_DEBUG` = `0`

Do not commit real database credentials or secrets to GitHub.

## Important Render note

Render web services use an ephemeral filesystem by default, so SQLite is not suitable as the production database. This project therefore uses PostgreSQL whenever `DATABASE_URL` is present.

The Render free PostgreSQL offering has a limited lifetime according to current Render documentation. For a long-term college-project URL, use a paid/persistent database plan when needed.

## Local test

Without `DATABASE_URL`, the app uses SQLite:

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python app.py
```

Then open:

`http://127.0.0.1:5000`

For local PostgreSQL instead, set `DATABASE_URL` before starting the app.

## Database behavior

On first startup, the app creates its tables and inserts the demo users/books if the database is empty. This is intended for a fresh capstone deployment.

If you later deploy a new version against an existing database, the `CREATE TABLE IF NOT EXISTS` statements preserve existing data. For a larger production system, use a migration tool such as Alembic/Flask-Migrate rather than changing schema manually.
